## 1. 1주차 — 알고리즘이란 (Ch.1.1)

### 1-1. 정의와 성질
- **알고리즘:** 문제를 푸는 **명확하게 정의된 유한한 단계**. 입력 → 처리 → 출력
- 핵심 성질 4가지: **정확성**(모든 유효 입력에 올바른 결과) · **유한성**(반드시 종료) · **명확성**(모호하지 않음) · **효율성**(시간·공간을 합리적으로 사용)
- 품질 4요소: **정확성 · 효율성 · 견고성(Robustness, 엣지 케이스·입력 검증) · 명확성(Clarity, 가독성)**

### 1-2. 의사코드
- 특정 언어에 독립적. 자연어 + 수학 기호. 제어 구조(if/else, for, while, return), 명확성, 일관성(변수명·들여쓰기·경계 조건)
```
Algorithm Max(A[1..n]):          // 전제: n ≥ 1
    max ← A[1]
    for i ← 2 to n do
        if A[i] > max then max ← A[i]
    return max                   // 비교 n−1회 → O(n)
```

### 1-3. 선형 탐색 vs 이진 탐색
| | 선형 탐색 | 이진 탐색 |
|---|---|---|
| 복잡도 | O(n) | O(log n) |
| 전제 | 없음 (정렬 불필요) | **정렬 필수** |
| 100만 건 | 평균 50만 번 비교 | 최대 약 20번 |

- ⭐ 트레이드오프: **정렬 비용 vs 탐색 빈도**. 정렬 안 된 데이터를 **1번만** 찾으면 선형 탐색, **여러 번** 찾으면 미리 정렬(O(n log n)) 후 이진 탐색

## 2. 2주차 — 복잡도와 점근 표기 (Ch.1.2~1.4)

### 2-1. 기본 개념
- **입력 크기 n:** 배열 원소 수, 그래프 노드 수 등
- **Basic operation:** 수행 시간을 대표하는 핵심 연산 (정렬은 **비교**, 합산은 **덧셈**). 실제 시간(초)은 하드웨어·언어마다 다르므로 **연산 횟수로 추상화**
- 왜 분석하나: basic operation이 1ns라도 입력 10억이면 **이차 알고리즘 ≈ 31.7년, n ln n 알고리즘 ≈ 29.9초**
- **시간복잡도:** n이 커질수록 수행 시간이 얼마나 증가? / **공간복잡도:** 추가 메모리가 얼마나 증가? (sum, i 같은 변수만 → O(1), 크기 n 배열 추가 → O(n))

### 2-2. 반복문 예제
| 코드 | 횟수 | 차수 |
|---|---|---|
| `for i=1..n: sum += A[i]` | n | O(n) |
| `for i=1..n: for j=1..n: count++` | n² | O(n²) |
| `for i=1..n: for j=i+1..n: count++` | (n−1)+…+1 = **n(n−1)/2** | O(n²) |

⚠️ "중첩 반복문 = 무조건 n²"으로 외우지 말고 **실제 범위를 계산**하는 습관

### 2-3. Exact vs Order
- Exact: n(n−1)/2 = ½n² − ½n / Order: **n²** (최고차항만, 계수·낮은 차수 무시)
- 예: 3n+7 → n, n²+10n → n², 5n³+n²+100 → n³
- ⚠️ 100n vs 0.01n²: **n < 10,000이면 이차식이 더 빠를 수 있음**. 큰 틀의 비교는 order가 핵심이지만 상수도 중요

### 2-4. ⭐⭐ 점근 표기 정의 (c, N 사용)
| 표기 | 정의 | 의미 |
|---|---|---|
| **g(n) ∈ O(f(n))** | 어떤 c > 0, N이 존재해 **모든 n ≥ N에서 g(n) ≤ c·f(n)** | 점근적 **상한** ("이보다 빨리 커지지 않는다") |
| **g(n) ∈ Ω(f(n))** | 어떤 c > 0, N이 존재해 모든 n ≥ N에서 **g(n) ≥ c·f(n)** | 점근적 **하한** |
| **g(n) ∈ Θ(f(n))** | c, d > 0, N 존재: **c·f(n) ≤ g(n) ≤ d·f(n)** = O ∩ Ω | **같은 차수** |
| **g(n) ∈ o(f(n))** | **모든** 양의 c에 대해 N이 존재해 n ≥ N에서 **g(n) < c·f(n)** | **엄격히 더 낮은 차수** |

- 예: 5n² ∈ O(n²) (c=5, N=0) / n²+10n ∈ O(n²) (c=2, N=10) / n²+10n ∈ Ω(n²) (c=1) → **Θ(n²)**
- ⚠️ 오해 3가지: ① Big-O는 정확한 실행 시간이 아니라 **상한** ② n ∈ O(n²)도 **참** ③ c와 N은 **유일하지 않음**
- ⚠️ **O(n²) ≠ Θ(n²)**: n ∈ O(n²)이지만 n ∉ Θ(n²) / **o vs Θ**: n² ∈ Θ(n²)이지만 n² ∉ o(n²)
- Big-O는 "어떤 c 하나"면 되지만, little-o는 "**모든** 양의 c"에 대해 성립해야 함
- **Theorem 1.2:** g ∈ o(f) ⇒ g ∈ O(f) − Ω(f) (상한은 맞지만 하한은 아님)

### 2-5. ⭐ 극한으로 차수 판정 (Theorem 1.3)
```
lim_{n→∞} g(n)/f(n) = c > 0  →  g ∈ Θ(f)
                    = 0      →  g ∈ o(f)
                    = ∞      →  f ∈ o(g)
```
- (n+100)/n → 1 ⇒ Θ(n) / (2n²+3n+1)/n² → 2 ⇒ Θ(n²) / (n log n)/n² = log n/n → 0 ⇒ n log n ∈ o(n²)
- **L'Hôpital:** lim (log x)/x = lim (1/x)/1 = 0 ⇒ log n ∈ o(n)
- 성장률 순서: **1 < log n < n < n log n < n² < n³ < 2ⁿ < n!** (log n ∈ o(√n), n² ∈ o(2ⁿ), n² log n ∈ o(n³))

### 2-6. 미니 퀴즈 (슬라이드)
n³+n의 차수? **Θ(n³)** / n² ∈ O(n³)? **예** / n² ∈ Ω(n)? **예** / n ∈ o(n²)? **예** / log n ∈ o(n)? **예 (L'Hôpital)**

## 3. 3주차 — 분할정복: 이진 탐색, 합병 정렬 (Ch.2)

### 3-1. 분할정복 3단계
**Divide**(같은 구조의 작은 문제로) → **Conquer**(재귀로 해결, 충분히 작으면 직접) → **Combine**(합침). 세 단계가 균등할 필요는 없음 (이진 탐색은 Combine 거의 없음)

### 3-2. 이진 탐색
```
location(low, high):
    if low > high: return 0(또는 -1)           // 실패
    mid = ⌊(low+high)/2⌋
    if x == S[mid]: return mid
    elif x < S[mid]: return location(low, mid−1)
    else: return location(mid+1, high)
```
- **T(n) = T(n/2) + c** → 펼치면 T(1) + c·log₂n → **Θ(log n)**
- 정렬돼 있어야 "가운데보다 크면 왼쪽엔 없다" → 절반을 버릴 수 있음
- 예: `[3,7,11,18,25,31,42,56,63,77,81]`에서 42 → mid 값 31 → 63 → 42 (**3번**), 19 → 31, 11, 18, 25 → low > high 실패

### 3-3. 합병 정렬
- **Divide는 쉽고 Combine(merge)이 핵심.** merge는 두 포인터로 Θ(n)
- **T(n) = 2T(n/2) + cn** → 레벨마다 cn × 레벨 log n개 = **Θ(n log n)** (항상)
- 추가 메모리 O(n). 비교 기반 정렬 하한 Θ(n log n) → 점근적으로 최적

| | 이진 탐색 | 합병 정렬 |
|---|---|---|
| 점화식 | T(n/2) + c | 2T(n/2) + cn |
| 재귀 호출 | 1개 | 2개 |
| 결합 비용 | 상수 | 선형 |
| 결과 | Θ(log n) | Θ(n log n) |

## 4. 4주차 — 마스터 정리, 퀵 정렬, Strassen (Ch.2)

### 4-1. ⭐⭐ 마스터 정리
```
T(n) = a·T(n/b) + f(n),   a ≥ 1, b > 1     기준값: n^(log_b a)
```
| Case | 조건 | 결과 | 직관 |
|---|---|---|---|
| 1 | f(n) = O(n^(log_b a − ε)), ε > 0 | Θ(n^(log_b a)) | 재귀(리프)가 지배 |
| 2 | f(n) = Θ(n^(log_b a) · logᵏn), k ≥ 0 | Θ(n^(log_b a) · log^(k+1) n) | 비슷함 |
| 3 | f(n) = Ω(n^(log_b a + ε)) **그리고 a·f(n/b) ≤ c·f(n), c < 1** | Θ(f(n)) | 분할·결합이 지배 |

**답안 예시 (감점 없는 형식)** — T(n) = 4T(n/2) + n
```
① T(n) = aT(n/b) + f(n) 꼴
② a = 4, b = 2, f(n) = n
③ a = 4 ≥ 1, b = 2 > 1 이므로 마스터 정리 적용 가능
④ n^(log_b a) = n^(log₂4) = n²
⑤ f(n) = n = O(n^(2−ε)), ε = 1 > 0 → Case 1
⑥ T(n) = Θ(n²)
```
| 점화식 | 답 |
|---|---|
| 2T(n/2) + n | Θ(n log n) (Case 2) |
| 2T(n/2) + n² | Θ(n²) (Case 3, 정규성 2(n/2)² = ½n² ✓) |
| 8T(n/2) + n² | Θ(n³) (Case 1) |
| 7T(n/2) + n² | Θ(n^(log₂7)) ≈ Θ(n^2.81) (Case 1) |
| T(n/2) + 1 | Θ(log n) (Case 2) |
| 3T(n/3) + n log n | Θ(n log² n) (Case 2, k=1) |
| T(n−1) + n | **적용 불가** → 펼쳐서 n(n+1)/2 = Θ(n²) |

### 4-2. 퀵 정렬
- Hoare(1960). **Pivot** 기준으로 작은 것 왼쪽 / 큰 것 오른쪽 → pivot은 **최종 위치 확정** → 양쪽 재귀
- ⭐ **분할(partition)이 핵심, 결합 없음.** (합병 정렬은 분할 단순, merge가 핵심)
- 중앙값을 pivot으로 못 쓰는 이유: 중앙값을 알려면 정렬해야 하는데 지금 정렬 중이라서
```
partition(A, low, high):
    pivot ← A[low]; j ← low
    for i ← low+1 to high:
        if A[i] < pivot: j ← j+1; swap(A[i], A[j])
    swap(A[low], A[j])          // ⚠️ 마지막 pivot swap
    return j
```
- 수업 추적: `[7,2,1,6,8,5,3,4]`, pivot 7 → **[4,2,1,6,5,3,7,8]**, 7은 인덱스 6
- partition은 한 번 훑음 → f(n) = Θ(n)

| | Best | Average | Worst |
|---|---|---|---|
| 상황 | 항상 중앙값 | 무작위 | 항상 최소/최대 (**이미 정렬된 배열 + 고정 pivot**) |
| 점화식 | 2T(n/2) + n | (2/n)ΣT(k) + n | **T(n−1) + n** |
| 결과 | Θ(n log n) | **Θ(n log n)** | **Θ(n²)** |

- 그래도 쓰는 이유: 평균 n log n, **in-place**(추가 배열 없음, 재귀 스택 O(log n)), 상수 작음·캐시 효율. 최악 회피: random pivot, median-of-three, 작은 구간은 insertion sort, introsort

### 4-3. 행렬 곱셈과 Strassen
- 표준: C[i][j] = Σ A[i][k]B[k][j] → 3중 루프 **Θ(n³)**
- 4블록 단순 분할: 부분행렬 곱 8번 → **T(n) = 8T(n/2) + Θ(n²) = Θ(n³)**. ⭐ "분할했다고 다가 아니다" — 재귀 호출 때문에 상수는 오히려 커짐. **a를 줄여야** 지수가 내려간다
- **Strassen(1969):** 곱셈 8 → **7**, 덧셈·뺄셈 증가 → **T(n) = 7T(n/2) + Θ(n²) = Θ(n^2.81)**
```
M1=(A11+A22)(B11+B22)  M2=(A21+A22)B11  M3=A11(B12−B22)  M4=A22(B21−B11)
M5=(A11+A12)B22        M6=(A21−A11)(B11+B12)  M7=(A12−A22)(B21+B22)
C11=M1+M4−M5+M7   C12=M3+M5   C21=M2+M4   C22=M1−M2+M3+M6
```
- 실제로 항상 빠르지 않은 이유 3가지: **재귀 호출 오버헤드, 수치 안정성(부동소수점 오차 누적), 캐시 효율** → threshold 이하는 표준 알고리즘
- 이후 n^2.37 수준까지 내려왔지만 진짜 하한은 **미해결**. 행렬 곱은 원소끼리 독립이라 **병렬 처리** 예제로 자주 쓰임

## 5. 5주차 — DP: 이항계수, Floyd (Ch.3.1~3.2)

### 5-1. DP 기본
- **같은 부분 문제가 반복**되면 저장해서 재사용 (메모이제이션 top-down / 테이블 bottom-up)
- 적용 조건: **최적 부분 구조 + 중복 부분 문제**
- 설계 4단계: **상태 정의 → 점화식 → 초기값 → 계산 순서**

| | 분할정복 | DP |
|---|---|---|
| 부분 문제 | 독립적 | **겹침** |
| 방식 | top-down 분할·결합 | 저장·재사용 (주로 bottom-up) |
| 예 | 합병·퀵 정렬, 이진 탐색 | 이항계수, Floyd, 연쇄행렬곱, 최적 BST |

### 5-2. 이항계수
```
B[i][j] = B[i−1][j−1] + B[i−1][j]   (0 < j < i)
B[i][0] = B[i][i] = 1
```
- "특정 원소를 포함 / 미포함"으로 나눔. 순수 재귀는 지수 시간(중복 계산), DP는 **Θ(nk)**, 1차원 배열로 공간 O(k) 가능 (j를 역방향으로)
- C(6,3) 표의 마지막 행: 1, 6, 15, **20**

### 5-3. ⭐⭐ Floyd(-Warshall)
```
D⁽ᵏ⁾[i][j] = 중간 정점으로 {v1..vk}만 사용할 때 i→j 최단거리
D⁽ᵏ⁾[i][j] = min( D⁽ᵏ⁻¹⁾[i][j],  D⁽ᵏ⁻¹⁾[i][k] + D⁽ᵏ⁻¹⁾[k][j] )
D⁽⁰⁾ = 인접 행렬 W (i=j면 0, 간선 없으면 ∞)
```
```
for k = 1..n          // ⭐ k가 반드시 가장 바깥
  for i = 1..n
    for j = 1..n
      D[i][j] = min(D[i][j], D[i][k] + D[k][j])
```
- 시간 **Θ(n³)**, 공간 Θ(n²) (in-place 가능: k단계에서 k행·k열은 안 바뀜)
- k가 바깥인 이유: D⁽ᵏ⁾를 구하려면 D⁽ᵏ⁻¹⁾가 **완전히** 완성돼 있어야 함
- 음수 간선 처리 가능, 음수 사이클은 끝난 뒤 **D[i][i] < 0**으로 감지만 가능
- 예제(1→2:3, 1→4:7, 2→3:2, 2→4:5, 3→4:1): k=2에서 D[1][3]=5, k=3에서 D[1][4]=6, D[2][4]=3

## 6. 6주차 — DP 최적화: 연쇄행렬곱셈, 최적 BST (Ch.3.3~3.5)

### 6-1. 최적화 문제와 최적성의 원리
- **최적화 문제:** 가능한 해(feasible solution)가 여러 개이고 그중 비용 최소 / 이익 최대를 찾는 문제 (최단 경로, 배낭, 최소 곱셈 횟수)
- ⭐ **최적성의 원리 (Principle of Optimality):** 문제의 최적해는 **부분 문제의 최적해를 포함**한다. 이게 성립해야 DP 적용 가능
  - 예: A→C 최단경로가 A→B→C이면 A→B 구간도 최단이어야 함 (아니면 더 줄일 수 있으니 모순)

### 6-2. ⭐⭐ 연쇄행렬곱셈 (Chained Matrix Multiplication)
- A_i의 크기 = **d[i−1] × d[i]**. (p×q)·(q×r) 곱셈 = **p·q·r번** scalar multiplication
- 결합법칙 때문에 결과는 같지만 괄호 위치에 따라 비용이 크게 다름
  - d = [10, 100, 5, 50]: (A1A2)A3 = 5,000 + 2,500 = **7,500** / A1(A2A3) = 25,000 + 50,000 = **75,000** (10배)
- 괄호 방법 수는 카탈란 수 → 지수적 (n=10이면 4,862가지, n=20이면 약 17억)

```
M[i][j] = 0                                                  (i = j)
M[i][j] = min_{i ≤ k < j} ( M[i][k] + M[k+1][j] + d[i−1]·d[k]·d[j] )   (i < j)
```
- 세 항: 왼쪽 최소 비용 + 오른쪽 최소 비용 + **마지막 결합 비용 d[i−1]·d[k]·d[j]**
- **P[i][j] = 최소를 만든 k** (괄호 복원용)

```
MinimumMultiplications(d, n):
  for i = 1..n: M[i][i] = 0
  for diagonal = 1..n−1:                 // 구간 길이 짧은 것부터
    for i = 1..n−diagonal:
      j = i + diagonal; M[i][j] = ∞
      for k = i..j−1:
        cost = M[i][k] + M[k+1][j] + d[i−1]*d[k]*d[j]
        if cost < M[i][j]: M[i][j] = cost; P[i][j] = k
```
- ⭐ **diagonal 순서인 이유:** M[i][j]는 더 짧은 구간 값만 참조 → 짧은 구간부터 채워야 참조할 값이 이미 계산돼 있음. "**DP는 계산 순서가 곧 알고리즘 구조다**"
- 복잡도: 부분 문제 O(n²) × 분할점 O(n) = **O(n³)** 시간, **O(n²)** 공간

**⭐ 예제:** d = [5, 2, 3, 4, 6] (A1 5×2, A2 2×3, A3 3×4, A4 4×6)
| 계산 | 후보 | 결과 |
|---|---|---|
| M[1][2] | 5·2·3 | **30**, P=1 |
| M[2][3] | 2·3·4 | **24**, P=2 |
| M[3][4] | 3·4·6 | **72**, P=3 |
| M[1][3] | k=1: 0+24+5·2·4=**64** / k=2: 30+0+5·3·4=90 | **64**, P=1 |
| M[2][4] | k=2: 0+72+2·3·6=108 / k=3: 24+0+2·4·6=**72** | **72**, P=3 |
| M[1][4] | k=1: 0+72+5·2·6=**132** / k=2: 30+72+90=192 / k=3: 64+0+120=184 | **132**, P=1 |

M 표 (위 삼각): 1행 [0, 30, 64, 132] / 2행 [–, 0, 24, 72] / 3행 [–, –, 0, 72]
최적 순서: P[1][4]=1 → A1 | (A2A3A4), P[2][4]=3 → (A2A3) | A4 ⇒ **A1((A2A3)A4)**
> ⚠️ 슬라이드 p13에는 "((A1(A2A3))A4)"라고 적힌 곳이 있는데, P 표를 따라가면 **A1((A2A3)A4)**가 맞음 (p12 표기가 정답)

```
PrintOptimalOrder(P, i, j):
  if i == j: print "A" + i
  else: print "("; k = P[i][j]
        PrintOptimalOrder(P, i, k); PrintOptimalOrder(P, k+1, j); print ")"
```
- 복원은 비용을 다시 계산하지 않고 P만 따라감 → **O(n)**. 계산(O(n³))과 복원은 별개 알고리즘

### 6-3. ⭐⭐ 최적 이진탐색트리 (Optimal BST)
- 정렬된 키 K1 < … < Kn, 각 키의 검색 빈도(확률) pᵢ. **평균 탐색 비용 Σ pᵢ·(깊이ᵢ + 1)** 최소인 BST
  - (깊이+1) = 비교 횟수 (루트 1번, 깊이 1은 2번 …)
- **최적 BST ≠ 균형 BST.** 자주 찾는 키를 루트 가까이
- **Greedy(빈도 최대를 루트로)로는 전역 최적 보장 안 됨** → DP 필요

```
A[i][j] = 0                                         (i > j, 빈 구간)
A[i][i] = pᵢ
A[i][j] = min_{i ≤ k ≤ j} ( A[i][k−1] + A[k+1][j] ) + Σ_{m=i..j} p_m
```
- ⭐ **왜 Σp_m (= W(i,j))을 더하나:** 루트 Kₖ 아래 붙으면 부분트리의 모든 키 **깊이가 1 증가** → 각 키 비용이 pₘ씩 증가. 루트 자신의 비용 pₖ×1도 이 합에 포함
- 연쇄행렬곱과 차이: 분할점이 k(i ≤ k **<** j) vs 루트 k(i ≤ k **≤** j), 추가 항이 d·d·d vs **W(i,j)**
- **R[i][j] = 최적 루트**. 시간 **O(n³)**, 공간 O(n²)

**⭐ 예제:** p1=3 (A), p2=2 (B), p3=5 (C)
| 계산 | 후보 | 결과 |
|---|---|---|
| A[1][2], W=5 | k=1: 0+2+5=**7** / k=2: 3+0+5=8 | 7, R=1 |
| A[2][3], W=7 | k=2: 0+5+7=12 / k=3: 2+0+7=**9** | 9, R=3 |
| A[1][3], W=10 | k=1: 0+9+10=19 / k=2: 3+5+10=18 / k=3: 7+0+10=**17** | **17**, R=3 |

최적 트리: 루트 **C**, C의 왼쪽 자식 **A**, A의 오른쪽 자식 **B** (비용 5·1 + 3·2 + 2·3 = 17)
비교: B 루트(균형) = 18, A 루트 = 19

```
PrintOptimalBST(R, i, j):
  if i > j: print "NIL"
  else: r = R[i][j]; print K[r]
        PrintOptimalBST(R, i, r−1); PrintOptimalBST(R, r+1, j)
```

### 6-4. 두 문제의 공통 뼈대
| | 연쇄행렬곱셈 | 최적 BST |
|---|---|---|
| 핵심 질문 | 어디서 나눌까 (분할점 k) | 누구를 루트로 (루트 k) |
| 비용 | 왼쪽 + 오른쪽 + d[i−1]d[k]d[j] | 왼쪽 + 오른쪽 + W(i,j) |
| 비용 표 / 선택 표 | M / P | A / R |
| 복잡도 | O(n³) / O(n²) | O(n³) / O(n²) |

> DP 원칙: **최적값과 최적 선택을 쌍으로 저장해야** 실제 해(구조)를 복원할 수 있다

## 7. 7주차 — Greedy, MST, Prim (Ch.4 도입~4.1.1)

### 7-1. Greedy 접근법
- 매 단계 **지금 가장 좋아 보이는 선택 하나를 즉시 확정**, 번복하지 않음. 저장·참조 안 해서 단순하고 빠름
- 항상 최적은 아님. **탐욕적 선택 속성(Greedy Choice Property) + 최적 부분 구조**를 만족해야 최적 보장 → **반드시 검증 필요**

| | DP | Greedy |
|---|---|---|
| 방식 | 모든 부분 문제 해를 테이블에 저장, 모든 경우 고려 후 결정 | 현재 최선 하나를 즉시 확정 |
| 비용 | 시간·공간 상대적으로 큼 | 단순·빠름 |
| 최적성 | 최적성의 원리만 성립하면 보장 | 적용 조건 검증 필요 |
| 예 | 이항계수, Floyd, 연쇄행렬곱, 최적 BST, 0-1 Knapsack | MST(Prim, Kruskal), 활동 선택, Huffman |
| 실패 예 | | 0-1 Knapsack, 최적 BST |

### 7-2. 그래프 용어와 Spanning Tree
- 가중치 그래프, **연결 그래프**(모든 정점 쌍에 경로 존재), 사이클, 트리 = 사이클 없는 연결 그래프
- **Spanning Tree:** ① 모든 정점 포함 ② 간선 **정확히 n−1개** ③ 사이클 없음 ④ 연결됨. 한 그래프에 여러 개 존재 가능
- **MST:** 모든 spanning tree 중 **간선 가중치 합이 최소**인 것
  - 연결 그래프에서만 정의 (비연결이면 spanning forest)
  - 가중치가 모두 다르면 MST는 **유일**, 같은 값이 있으면 여러 개일 수 있음
  - 응용: 통신망·전력망·도로망을 최소 비용으로 연결
- ⚠️ **MST ≠ 최단경로(Dijkstra).** Dijkstra는 한 출발점에서 각 정점까지 경로 비용 최소, MST는 **전체 연결 비용** 최소. MST 위의 두 정점 경로가 최단경로라는 보장 없음

### 7-3. ⭐⭐ Prim 알고리즘
- 정점 집합 **Y(트리에 포함)** 와 **V−Y** 를 나누고, 매 단계 **Y와 V−Y를 잇는 간선 중 최소 가중치**를 골라 그 정점을 Y에 추가. Y = V가 되면 종료 (n−1번 선택)
- ⚠️ "전체 그래프에서 가장 싼 간선"이 아니라 "**현재 트리에 연결된** 간선 중 가장 싼 것" (전체에서 고르는 건 Kruskal)
- 근거 (**Cut Property**): Y와 V−Y를 가로지르는 가장 가벼운 간선은 어떤 MST에 반드시 포함됨
- 시작 정점은 아무거나 (가중치가 모두 다르면 결과 MST 동일)

```
Prim(G):                       // high-level
  F ← ∅; Y ← {v1}
  while Y ≠ V:
    e = (u, v) ← argmin{ w(u,v) | u ∈ Y, v ∈ V−Y }
    F ← F ∪ {e}; Y ← Y ∪ {v}
  return F
```

**구현: nearest / distance 배열 (인접행렬 W)**
- **nearest[i]** = Y 안에서 vᵢ와 가장 가깝게 연결되는 정점의 인덱스 (초기 1)
- **distance[i]** = vᵢ를 현재 트리에 붙이는 최소 비용 (초기 W[1][i]). **−1이면 이미 Y에 포함**
```
F ← ∅
for i = 2..n: nearest[i] ← 1; distance[i] ← W[1][i]
repeat (n−1) times:
    min ← ∞
    for i = 2..n:                              // ① 최솟값 탐색 O(n)
        if 0 ≤ distance[i] < min: min ← distance[i]; vnear ← i
    F ← F ∪ {(nearest[vnear], vnear)}          // ② 간선 추가
    distance[vnear] ← −1                       //    Y에 포함 표시
    for i = 2..n:                              // ③ 갱신 O(n)
        if W[i][vnear] < distance[i]:
            distance[i] ← W[i][vnear]; nearest[i] ← vnear
```
- ⚠️ Prim의 distance = "**현재 트리와 v를 잇는 최소 비용**" / Dijkstra의 distance = "**출발점에서 v까지 최단 경로 비용**"
- **복잡도:** (n−1)번 × (O(n) 탐색 + O(n) 갱신) = **Θ(n²)** (every-case). 교재: T(n) = 2(n−1)(n−1)
  - 이진 힙: O((n+m) log n) → sparse 그래프 유리 / 피보나치 힙: O(m + n log n) (심화)
  - 인접행렬 Θ(n²)는 dense 그래프에 적합

**⭐ 예제 추적:** 간선 A-B 1, B-C 2, C-E 2, A-C 3, C-D 4, D-E 5, B-D 6, 시작 A
| 단계 | Y | 후보 (Y→V−Y) | 선택 | 누적 |
|---|---|---|---|---|
| 1 | {A} | A-B 1, A-C 3 | **A-B (1)** | 1 |
| 2 | {A,B} | B-C 2, A-C 3, B-D 6 | **B-C (2)** | 3 |
| 3 | {A,B,C} | C-E 2, C-D 4, B-D 6 (A-C는 둘 다 Y라 무시) | **C-E (2)** | 5 |
| 4 | {A,B,C,E} | C-D 4, E-D 5, B-D 6 | **C-D (4)** | **9** |

배열로 보면 (B,C,D,E 순서의 distance / nearest):
| 단계 | distance | nearest | 선택 |
|---|---|---|---|
| 초기 | 1, 3, ∞, ∞ | A, A, A, A | |
| B 추가 후 | −1, **2**, **6**, ∞ | A, **B**, **B**, A | (A,B) |
| C 추가 후 | −1, −1, **4**, **2** | A, B, **C**, **C** | (B,C) |
| E 추가 후 | −1, −1, 4, −1 | (D: 5 < 4 아님, 그대로) | (C,E) |
| D 추가 후 | 모두 −1 | | (C,D) |

MST 총 비용 **9**, 정점 5개 → 간선 **4개 (n−1)**, 반복 4번

- **사이클이 안 생기는 이유:** 매번 트리 **밖의 새 정점**만 추가 → 이미 트리 안에 있는 두 정점을 잇는 간선은 절대 추가 안 함
- **항상 연결인 이유 (귀납법):** 시작 정점 하나는 연결 / k번째까지 연결이면, 새 정점은 트리 안 정점과 간선으로 이어지므로 k+1번째도 연결 → n−1개 간선의 연결 그래프 = spanning tree
- 한계: MST 문제 전용, **최단경로 문제는 못 풂**

### 7-4. Prim vs Kruskal (8주차 예고, 비교는 알아두기)
| | Prim | Kruskal |
|---|---|---|
| 기준 | **정점 중심**, 하나의 트리를 키움 | **간선 중심**, 간선을 가중치 순 정렬 후 선택 |
| 사이클 처리 | 구조상 안 생김 | 사이클이 생기면 건너뜀 (**Union-Find**) |
| 중간 상태 | 항상 연결된 트리 하나 | 여러 컴포넌트(숲)가 합쳐짐 |
| 복잡도 | Θ(n²) (인접행렬), 힙 O(E log V) | O(E log E) |
| 유리 | dense 그래프 | sparse 그래프 |

## 8. 📘 교재 전용 내용 모음 (20%)

> 강의 슬라이드에는 없거나 짧게만 언급됐지만 교재 범위에 포함된 내용입니다.

### Ch.1
- **분석의 종류:** every-case T(n) / worst-case W(n) / average-case A(n) / best-case B(n). 입력 값과 상관없이 횟수가 같으면 every-case
- **순차 탐색 평균:** x가 S에 반드시 있고 위치가 균등 → **A(n) = (n+1)/2**. x가 S에 있을 확률이 p이면 **A(n) = n(1 − p/2) + p/2**
- **교환 정렬(Exchange Sort):** 비교 횟수 every-case **T(n) = n(n−1)/2**
- **행렬 곱셈(표준):** 곱셈 횟수 T(n) = n³
- **피보나치:** 재귀 버전은 계산하는 항의 수 **T(n) > 2^(n/2)** (지수), 반복 버전은 **n+1**개 항 (선형). → 같은 문제도 알고리즘에 따라 지수 vs 선형
- **차수의 성질 (Ch.1.4):**
  - g ∈ O(f) ⇔ f ∈ Ω(g) / g ∈ Θ(f) ⇔ f ∈ Θ(g)
  - a, b > 1이면 **log_a n ∈ Θ(log_b n)** (로그 밑은 차수에 무관)
  - b > a > 0이면 **aⁿ ∈ o(bⁿ)** (지수 함수는 밑이 다르면 차수가 다름!)
  - 모든 a > 0에 대해 **aⁿ ∈ o(n!)**
  - 복잡도 순서: Θ(lg n), Θ(n), Θ(n lg n), Θ(n²), Θ(nʲ), Θ(nᵏ), Θ(aⁿ), Θ(bⁿ), Θ(n!) (k > j > 2, b > a > 1)
  - c ≥ 0, d > 0이고 g ∈ O(f), h ∈ Θ(f)이면 c·g + d·h ∈ Θ(f) (합은 큰 쪽 차수)

### Ch.2
- **이진 탐색 최악:** W(n) = **⌊lg n⌋ + 1** (비교 횟수)
- **합병 정렬 최악 비교 횟수:** W(n) = **n lg n − (n − 1)** ∈ Θ(n lg n). 추가 공간: 단순 버전 약 2n, Mergesort 2(인덱스 사용) Θ(n)
- **퀵 정렬:** 최악 W(n) = **n(n−1)/2**, 평균 **A(n) ≈ 1.38(n+1) lg n** ∈ Θ(n lg n)
- **Strassen 정확한 횟수:** 곱셈 **n^(lg 7) ≈ n^2.81**, 덧셈/뺄셈 **6n^(lg 7) − 6n²** (표준: 곱셈 n³, 덧셈 n³ − n²)
- **큰 정수 곱셈 (2.6):** n자리 수를 반으로 나눠 u = x·10^m + y, v = w·10^m + z
  - 곱 4번: W(n) = 4W(n/2) + cn → **Θ(n²)** (개선 없음)
  - (x+y)(w+z)를 이용해 **곱 3번**: W(n) = 3W(n/2) + cn → **Θ(n^(lg 3)) ≈ Θ(n^1.58)** (Strassen과 같은 발상)
- **임계값(threshold) 결정 (2.7):** 재귀 알고리즘과 단순 알고리즘의 실행 시간이 같아지는 n이 최적 임계값. 그 이하에서는 단순 알고리즘 호출
- **분할정복을 쓰면 안 되는 경우 (2.8):**
  1. 크기 n 문제를 **거의 n 크기**의 문제 2개 이상으로 나눌 때 → 지수 시간 (예: 재귀 피보나치)
  2. 크기 n 문제를 크기 n/c인 문제 **거의 n개**로 나눌 때 → n^Θ(lg n)

### Ch.3
- **DP 최적화 문제 3단계:** ① 최적해를 주는 재귀 성질 수립 ② 상향식으로 최적값 계산 ③ 최적해 구성
- **최적성의 원리가 성립하지 않는 예:** **최장 단순 경로(Longest Simple Path)** — 전체 최장 경로의 부분 경로가 그 구간의 최장 경로가 아닐 수 있음 → DP 적용 불가
- **이항계수 DP:** 반복 횟수 (2n − k + 2)(k + 1)/2 ∈ Θ(nk)
- **Floyd 경로 출력 (Algorithm 3.4):** P[i][j] = i→j 최단경로의 **가장 큰 인덱스 중간 정점** (없으면 0). 갱신될 때 P[i][j] ← k
```
path(q, r):
  if P[q][r] ≠ 0:
      path(q, P[q][r]); print "v" + P[q][r]; path(P[q][r], r)
```
- **연쇄행렬곱 정확한 횟수:** every-case **n(n−1)(n+1)/6** ∈ Θ(n³). 가능한 순서 수 tₙ ≥ 2^(n−2)
- **최적 BST (교재 형식):** pᵢ는 확률, 평균 탐색 시간 Σ cᵢpᵢ (cᵢ = 깊이+1). every-case **n(n−1)(n+4)/6** ∈ Θ(n³)
- **외판원 문제 (TSP, 3.6):** 모든 정점을 한 번씩 방문하고 돌아오는 최소 일주 경로
  - D[vᵢ][A] = A의 모든 정점을 한 번씩 거쳐 vᵢ에서 v1로 가는 최단 경로 길이
  - **D[vᵢ][A] = min_{vⱼ ∈ A} ( W[i][j] + D[vⱼ][A − {vⱼ}] )**, D[vᵢ][∅] = W[i][1]
  - 답: D[v1][V − {v1}]. 시간 **Θ(n²·2ⁿ)**, 공간 Θ(n·2ⁿ) (완전탐색 (n−1)!보다 훨씬 낫지만 여전히 지수)
- **서열 정렬 (Sequence Alignment, 3.7):** 두 DNA 서열을 정렬해 비용 최소화. 불일치(mismatch) 벌점 1, 틈(gap) 벌점 2
  - opt(i, j) = min( opt(i+1, j+1) + 벌점(0 또는 1), opt(i+1, j) + 2, opt(i, j+1) + 2 )
  - 표를 끝에서부터 채움, Θ(mn)

### Ch.4 (도입 ~ Prim)
- **Greedy 알고리즘 구성 3단계:** ① **선택 절차(selection procedure)** ② **적정성 검사(feasibility check)** ③ **해답 점검(solution check)**
- **거스름돈 문제:** 미국 동전(25, 10, 5, 1)은 greedy가 최적. 그러나 **12센트 동전**이 추가되면 16센트: greedy = 12+1+1+1+1 (**5개**) vs 최적 = 10+5+1 (**3개**) → greedy 실패 예
- **Prim 정확성 증명:**
  - **Promising(유망한) 집합:** 간선 집합 F가 어떤 MST의 부분집합이면 promising
  - **Lemma 4.1:** F가 promising이고 Y가 F의 정점 집합일 때, Y와 V−Y를 잇는 최소 가중치 간선 e에 대해 **F ∪ {e}도 promising**
  - **Theorem 4.1:** Prim은 항상 MST를 만든다 (Lemma 4.1과 귀납법: 공집합은 promising → 매 단계 promising 유지 → 최종 F는 MST)
- **Prim every-case:** **T(n) = 2(n−1)(n−1)** ∈ Θ(n²)

**세 전략 한 줄 비교**
- **분할정복:** 독립된 작은 문제로 나눠 재귀 (top-down)
- **DP:** 겹치는 부분 문제를 저장·재사용, 최적성의 원리 필요 (bottom-up)
- **Greedy:** 매 순간 최선을 확정, 번복 없음. 빠르지만 최적성 검증 필요
